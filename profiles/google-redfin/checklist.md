# google-redfin — bring-up checklist

Generated by porthole from the milestone table. `porthole next`
reads it, and **a probe always outranks a tick**: where the tool can
check something itself, this file is a second opinion.

    porthole next              where am I, and what is next
    porthole next --regenerate rebuild this file, keeping ticks


## before the device

- [x] Read the laws — ten notes, and they are what stops you wasting weeks <!-- read-laws -->
      Every one of them was learned by losing a session to it.
- [ ] SoC identified in the profile <!-- soc -->
      Nearly every later answer is looked up by SoC.
- [ ] Closest pmaports sibling found (or established that there is none) <!-- sibling -->
      A sibling's deviceinfo holds values that are known to boot. Guessing them costs days.
- [ ] Host identity configured <!-- identity -->
      Without it every tool resolves the wrong device, or none.

## first boot

- [ ] Boot image offsets sourced, not guessed <!-- offsets -->
      A wrong offset produces a device that does not boot and gives no diagnostic at all.
- [x] Established whether this device can RAM-boot at all <!-- ram-boot-known -->
      `fastboot boot` is the usual safety net and it is NOT universal. Where it is absent, every test image is a flash.
- [ ] A/B slot policy set before the first write <!-- slot-policy -->
      Recovery depends on a known-good image on the other slot. After the first bad flash is too late to decide this.
- [ ] Device tree named in the profile <!-- dtb-named -->
      The build and the boot image both resolve it from here.
- [ ] Device tree source exists in the working repo <!-- dts -->
      A mainline DTS is layered; the SoC dtsi may already be written.
- [ ] Device tree compiles <!-- dts-compiles -->
      dtc is the only thing that catches an unresolved phandle or an overlapping region.
- [ ] An offline gate exists (verify.sh) <!-- verify -->
      One command that checks everything checkable without hardware is what keeps a locked or absent device from stopping all work.
- [ ] A channel out that works before the display: earlycon, UART or gadget <!-- console -->
      A boot that fails before console handover says nothing on screen. A UART needs no userspace at all.
- [ ] The kernel boots far enough to say so <!-- first-boot -->
      Everything after this is debugging; everything before is guessing.

## storage, usb, ssh

- [ ] Storage probes and partitions enumerate <!-- storage -->
      Without it the rootfs never appears and the boot looks exactly like a hang.
- [ ] ssh answers on the device <!-- ssh -->
      Almost every tool in the box needs it.
- [ ] Passwordless sudo installed ON THE DEVICE <!-- sudo -->
      Tools call `sudo -n`, which never prompts — it just fails. Without this the whole toolbox silently does nothing.
- [ ] porthole doctor is clean <!-- doctor -->
      It is the difference between a broken port and a broken host.
- [ ] Reboot budget MEASURED, not estimated <!-- budget -->
      Every unattended wait uses it. An estimate that is too short reports failures that did not happen.

## packaging

- [ ] pmaports device package exists <!-- device-pkg -->
      Nothing installs without it.
- [ ] pmaports kernel package exists <!-- kernel-pkg -->
      It pins the tree and the config the port actually builds.
- [x] The packages build <!-- builds -->
      A package that builds on your host is the first thing anyone else can reproduce.

## subsystems

- [ ] Display brings up <!-- display -->
      Until it does, every boot verdict comes from a log rather than a screen — and a screen can lie either way.
- [ ] Suspend and resume survive a cycle <!-- suspend -->
      This dominates whether the port is a daily driver.
- [ ] Wifi, bluetooth, modem <!-- radios -->
      The last things that make a phone a phone.

## upstream

- [ ] What this port cost you is written down <!-- brain -->
      This project exists to share knowledge, not to fix one phone. A session that learned something and wrote nothing down is unfinished.
- [ ] Commits written as if being sent today <!-- upstream -->
      Anything that benefits other SoCs is worth splitting out while you still remember why.

---

Ticking a box that a probe can check does nothing: the probe wins.
Tick the ones nothing can see for you — reading the laws, the
first boot, the console you got working at 3am.
