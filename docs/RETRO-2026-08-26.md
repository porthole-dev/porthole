# Retro: one long taimen session, what the toolbox got wrong

Written after a day on call audio + a GPU wake crash. Ordered by cost.

## Flaky / wrong

1. **`porthole flash` re-verifies against a different tree than `build` used.**
   `PORTHOLE_KERNEL_TREE` was passed to `build` and not to `flash`, so flash
   compared the exported boot.img against the *stale* `.output` of the main
   checkout and printed `FAIL DTB MISMATCH -- DO NOT FLASH`. By then it had
   **already written the rootfs**. Worst failure of the day: a scary, wrong
   error on a half-flashed device. Flash must record what build used, not
   re-derive it.

2. **`porthole build kernel` does not flash**, but the rung table says
   "reflash both". It builds, installs a rootfs and verifies. The flash is a
   separate verb. Rename the rung or make it flash.

3. **`_PH_TREE` was hardcoded** to `$PORTHOLE_WORKDIR/linux` while
   `PORTHOLE_KERNEL_TREE` was honoured by dts/kconfig/verify. Series often
   live in worktrees; switching the main checkout to reach them is how a
   half-finished branch gets flashed. Fixed this session.

4. **`doctor` does not check envkernel.** `build kernel` died at step one with
   "cannot find envkernel.sh" on a fully working setup; the checkout was
   present at `~/src/pmbootstrap` and simply unconfigured. Doctor names every
   other fix; it should name this one.

5. **`tk-push-module.sh` assumes `.ko.xz`.** This rootfs ships uncompressed
   modules, so it warns "modprobe will not see this build" and then `insmod`
   fails `File exists` when the module is bound. It should handle plain `.ko`
   and say "in use, reboot to load" instead of an error that reads like a
   build failure.

6. **`tk-dmic-sweep.sh` cannot run in either place.** Header says "runs ON THE
   PHONE"; line 21 sources `../../../tools/tk-lib.sh`. It also stops greetd and
   kills the sound server, which is not something to discover mid-session.

7. **`porthole run` fails with a raw Python traceback** when a profile tool is
   not executable (`PermissionError` from posix_spawn). Should chmod, or run
   it through its interpreter, or say so in one line.

8. **`tk-capture.sh` fails silently when `sudo -n` is gone.** On a fresh
   rootfs it armed nothing and the channels were dead; the failure only showed
   up as an empty log much later. Arm-time check, loud.

## What I would improve

9. **A persistent scratch on the device.** Everything pushed to `/tmp` dies on
   reboot, and this session rebooted a dozen times -- every helper had to be
   re-pushed. A `porthole push` that installs to a persistent path would have
   saved an hour.

10. **`porthole experiment`.** Most of my wrong conclusions were confounds, not
    bad logic: leftover `aplay` holding a backend, PipeWire holding a PCM, a
    wedged ADSP from a previous run, blanking enabled. A verb that arms the
    capture, snapshots the mixer/profile/process state, runs the thing, and
    snapshots again would have caught every one of them. Three of today's
    "findings" were later refuted by exactly this class of state.

11. **A `tk_pkill` helper.** I killed my own ssh session with `pkill -f`
    twice. `brain/traps/a-journal-grep-matches-your-own-command-line.md`
    already names the trap; the fix is a function, not a note.

12. **Doctor should check the audio stack**, or more generally: the device
    package's declared dependencies vs what is installed. A rootfs reinstall
    silently swapped PipeWire for PulseAudio, whose capture is dead on this
    board, and nothing anywhere would have told us. The working configuration
    existed only as manual state on a filesystem that got replaced.

## What could have been better — about me, not the tools

13. **The laws are right and I broke them.** "Read the vendor before inventing
    a mechanism" and "an instrument that counts itself" are both in the brain,
    both cost me hours today, and both were violated *after* I had quoted them
    in my own output. The toolbox is not the weak part.

14. **I theorised against downstream instead of reading our own record.**
    `docs/CALL-AUDIO-2026-08-25.md` contained the answer, and explicitly
    refuted the two theories I then spent a day re-deriving. The brain should
    perhaps make prior *findings* as prominent as prior *traps* -- a trap says
    "do not do X", a finding says "X is already answered", and only the first
    is indexed by `porthole brain`.
